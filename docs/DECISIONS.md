# 技术决策记录

## 1. 向量数据库选型：ChromaDB vs FAISS vs Milvus

| 维度 | ChromaDB | FAISS | Milvus |
|------|----------|-------|--------|
| 部署复杂度 | 低（pip install） | 中 | 高（需 Docker） |
| 持久化 | 内置支持 | 需手动实现 | 内置支持 |
| 元数据过滤 | 支持 | 不支持 | 支持 |
| 适用规模 | 小中型（<100万） | 大型 | 超大型 |
| 生产就绪 | 一般 | 一般 | 高 |

**决策**：选用 **ChromaDB**，理由：
- 项目为 16 个文档、892 个 chunk，属于小型项目
- 内置持久化，无需额外配置
- 支持元数据过滤，方便溯源

---

## 2. Embedding 模型选型：BGE vs M3E vs text2vec

| 维度 | BGE-small-zh | M3E-base | text2vec-large |
|------|-------------|----------|----------------|
| 参数量 | 33M | 110M | 326M |
| 推理速度 | 快 | 中 | 慢 |
| 中文效果 | 优 | 良 | 优 |
| 内存占用 | 低 | 中 | 高 |

**决策**：选用 **BGE-small-zh-v1.5**，理由：
- 参数量小，推理速度快
- 中文效果好，适合本项目
- 内存占用低，适合本地部署

---

## 3. LLM 选型：DeepSeek vs Qwen vs GLM

| 维度 | DeepSeek-R1-7B | Qwen-7B | GLM-4-9B |
|------|---------------|---------|----------|
| 推理能力 | 强 | 中 | 中 |
| 中文能力 | 优 | 优 | 优 |
| API 价格 | 低 | 中 | 中 |
| 响应速度 | 快 | 快 | 中 |

**决策**：选用 **DeepSeek-R1-Distill-Qwen-7B**，理由：
- 推理能力强，适合 RAG 场景
- 通过阿里云百炼 API 调用，无需本地部署
- 价格低，适合测试和小规模生产

---

## 4. 框架选型：LangChain vs LlamaIndex

| 维度 | LangChain | LlamaIndex |
|------|-----------|------------|
| 生态丰富度 | 高 | 中 |
| 学习曲线 | 中 | 低 |
| RAG 专注度 | 中 | 高 |
| 灵活性 | 高 | 中 |

**决策**：选用 **LangChain**，理由：
- 生态丰富，支持多种向量数据库和 LLM
- 灵活性高，方便后续扩展
- 社区活跃，文档完善

---

## 5. Web 框架选型：FastAPI vs Flask

| 维度 | FastAPI | Flask |
|------|---------|-------|
| 异步支持 | 原生支持 | 需要扩展 |
| 性能 | 高 | 中 |
| 类型安全 | 高（Pydantic） | 低 |
| 学习曲线 | 中 | 低 |

**决策**：选用 **FastAPI**，理由：
- 原生异步支持，适合 I/O 密集型应用
- Pydantic 模型验证，减少 bug
- 自动生成 API 文档，方便调试

---

## 6. 测试策略：单元测试 + 集成测试

**决策**：
- **单元测试**：测试 `format_docs` 和 `calc_recall` 等纯函数
- **集成测试**：测试 RAG 完整流程（检索 → 格式化 → 召回率计算）
- **Mock 策略**：模块级初始化（embeddings + ChromaDB）在 CI 中跳过，只测试不依赖模型的函数

**理由**：
- CI 环境无法加载 Embedding 模型和向量库
- 核心逻辑（格式化、召回率）可以在无模型情况下测试
- 集成测试在本地运行，验证完整流程
