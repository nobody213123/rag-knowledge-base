# RAG 前沿技术与扩展方向

## 1. GraphRAG（图增强 RAG）

### 核心思想
将文档构建为知识图谱（实体-关系-实体），检索时不仅返回文本片段，还返回相关的实体关系链。

### 优势
- 适合多跳推理问题（如"张三的上司是谁？"需要先找到张三，再找到他的上司）
- 减少幻觉，因为关系链是显式建模的

### 实现路径
1. 用 LLM 从文档中抽取实体和关系
2. 存储到图数据库（如 Neo4j）
3. 检索时先图查询，再文本检索

### 适用场景
- 企业组织架构问答
- 产品参数关联查询

---

## 2. Self-RAG（自反思 RAG）

### 核心思想
LLM 在回答过程中自主决定是否需要检索、检索结果是否相关、回答是否有依据。

### 三类反思标记
1. **[Retrieve]**：是否需要检索？
2. **[IsRel]**：检索结果是否相关？
3. **[IsSup]**：回答是否被检索结果支持？

### 优势
- 减少不必要的检索，提升速度
- 提高回答质量，减少幻觉

### 实现路径
1. 在 Prompt 中加入反思指令
2. LLM 输出时生成反思标记
3. 根据标记决定是否继续检索或重新生成

---

## 3. HyDE（假设文档嵌入）

### 核心思想
先让 LLM 生成一个"假设性回答"，再用这个假设回答去检索，而不是用原始问题检索。

### 优势
- 假设回答与真实文档的语义更接近
- 适合问题和文档表述差异大的场景

### 实现路径
1. 用户提问 → LLM 生成假设回答
2. 用假设回答的 embedding 去检索
3. 用检索结果 + 原始问题生成最终回答

---

## 4. Multi-hop RAG（多跳检索）

### 核心思想
一次检索可能无法回答复杂问题，需要多轮检索-推理-再检索。

### 优势
- 适合复杂问题（如"对比 A 产品和 B 产品的退货政策"）
- 推理链路可追溯

### 实现路径
1. 第一轮检索：获取初步信息
2. LLM 分析：判断是否需要补充信息
3. 第二轮检索：针对缺口信息再次检索
4. 最终回答：综合所有检索结果

---

## 5. 上下文压缩（Context Compression）

### 核心思想
检索到的文档可能包含冗余信息，用 LLM 提取关键信息后再送入最终回答。

### 优势
- 减少 token 消耗
- 提高回答质量（去除噪声）

### 实现路径
1. 检索到 k 条文档
2. 用 LLM 提取每条文档的关键信息
3. 用压缩后的信息生成回答

---

## 6. 混合检索（Hybrid Search）

### 核心思想
结合关键词检索（BM25）和语义检索（向量），取长补短。

### 优势
- BM25 擅长精确匹配（如型号、编号）
- 向量检索擅长语义匹配（如同义词、近义词）

### 实现路径
1. 同时用 BM25 和向量检索
2. 对两路结果进行融合排序（RRF）
3. 返回融合后的 top-k 结果
